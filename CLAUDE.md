# CLAUDE.md

Firefox Developer Edition customization: `profile/chrome/userChrome.css` (with
`selected-tab-border.css`, imported at its top), `profile/chrome/userContent.css`,
`profile/user.js`. Read `README.md` and `scripts/README.md` first. Reply to the user in 繁體中文.

## Workflow

- **This repo is the source of truth.** Edit files here, never in the profile folder;
  `task deploy` (or a running `task watch`) copies them to the profile named in `.env`.
  `profile/` mirrors the Firefox profile folder: deploy copies its files (user.js) and mirrors
  its folders (chrome/: files missing from the repo are deleted from the profile); nothing
  else in the profile folder is touched. Only `user.js` and `chrome/` may be in `profile/`
  (deploy refuses anything else; `.gitignore` ignores it): never copy profile data in.
- Run everything through `Taskfile.yaml` (`task --list`). Add reusable scripts under
  `scripts/` and a task for them; keep one-off experiments out of the repo.
- Keep one `task watch` running in the background while editing CSS; it re-detects the
  Browser Toolbox port on every save, so it survives the toolbox being reopened.
- Before reporting work as done, run `task check` (Prettier on scripts/JSON/YAML, user.js
  checks) and `task diff`. Don't reorder user.js: it's grouped by hand.
- The Firefox version everything is tuned and checked against is stated in README.md (適用版本),
  the second line of `profile/user.js` and the TUNED FOR of both stylesheets. When it changes,
  follow README.md's upgrade steps and update all four together.
- `reference/` is generated by `task prefs:dump` (about:preferences' settings and their prefs);
  don't edit it by hand. Use it to find which pref a settings-page control writes.
  `about-preferences.current.js` holds personal values and is gitignored.
- Don't commit or push unless asked.
- Keep private data out of git and out of output: measurement output, screenshots and backups
  go to `scripts/out/` (ignored, like images anywhere); don't print tab URLs or other
  personal values in scripts' messages.
- Measurement output goes to `scripts/out/` (not committed). When the user is done with
  screenshots, move them to the Recycle Bin rather than deleting them.

## Verifying changes

- Measure, don't guess: `task eval -- <script.js or expression>` runs in the parent process;
  `--pid <os pid>` in a content process with chrome privileges (e.g. the new tab page,
  `browser.browsingContext.currentWindowGlobal.domProcess.osPid`); `--tab <url>` in a page.
  Report numbers (positions, gaps, radii, colors) against the design specs at the top of each
  CSS file.
- Screenshots: `task capture` grabs the real screen, but other windows on top get captured
  too, and it can't see covered areas. `drawSnapshot` (from a script) sees through other
  windows but misses popups, Mica and `backdrop-filter`. Say which one an image is.
- Before claiming a change is invisible-but-correct, diff pixels and show where they differ.
- When refactoring CSS or comments, prove the rules didn't change: compare the comment-free
  rules before and after (same set, same order where specificity ties).

## Touching the user's live Firefox

- Prefer temporary tabs for experiments: mark them (`tab.setAttribute("claude-temp", …)`),
  give them unique URLs, close them and restore the selected tab in a `finally`. Never
  interact with the user's own tabs (an earlier run put the user's about:config into edit
  mode by matching their tab).
- Pseudo-class locks (`InspectorUtils.addPseudoClassLock`), temporary user sheets
  (`nsIStyleSheetService`), opened sidebars, split views, tab-modal dialogs
  (`Services.prompt.asyncAlert(bc, Ci.nsIPrompt.MODAL_TYPE_TAB, …)`): always undo them and say
  so. Don't trigger window-modal or content `alert()` dialogs.
- **Never build a document by hand** (e.g. a windowless browser with
  `createAboutBlankDocumentViewer`): it crashed the whole browser
  (MOZ_RELEASE_ASSERT VerifyPartitionedPrincipalMatchesDocumentPrincipal).
- Don't change preferences, profiles.ini or prefs.js without asking. Edit profiles.ini and
  prefs.js only while Firefox is fully closed (check that no firefox.exe is left).
- `devtools.debugger.prompt-connection` is off for this workflow; remind the user to turn it
  back on when a session is over. user.js pins it to true, so a restart turns it back on (and
  the user has to turn it off again after a restart mid-session).

## CSS conventions

- Each file starts with TUNED FOR / DESIGN SPEC / WHEN A FIREFOX UPDATE BREAKS SOMETHING.
  Keep them current when the spec changes.
- Comment every rule with why, in the files' existing style: a `Firefox:` note naming the
  Firefox file/rule it overrides, `FRAGILE:` on anything relying on measured or hard-coded
  Firefox values.
- Override Firefox's variables (e.g. `--border-radius-large`, `--newtab-background-card`)
  rather than hard-coding values; spacing is on a 4px grid.
- Read Firefox's sources from the Browser Toolbox with
  `fetch("chrome://…")` / `fetch("resource://…")`. To search all of them, unzip
  `omni.ja` / `browser/omni.ja` from the install folder into a temporary folder, and delete
  it afterwards.

## Known limits (details in the CSS headers)

- From a user sheet, plain selectors reach into shadow DOM, but `::part()` and `:host()`
  don't, and selectors can't cross a shadow boundary. Custom properties and color-scheme
  inherit in: set variables on the host.
- `light-dark()` resolves where it's used; nova switches some elements to the light scheme.
  Use the registered `--custom-card-color` to resolve a color on the host.
- A `backdrop-filter` nested inside a frosted element only sees that element.
- Composite variables resolved at `:root` (e.g. moz-button's `--button-border`) must be
  overridden whole.
- `@property` can't be inside `@-moz-document`.
